# Auto Service AI Triage

API-сервис для первичной обработки обращений автосервиса. Он классифицирует
сообщение клиента, готовит черновик ответа, определяет необходимость передачи
обращения оператору и сохраняет историю обработки в SQLite.

## Возможности

- приём обращений через `POST /triage`;
- четыре категории: `billing`, `support`, `complaint`, `other`;
- структурированный JSON-ответ языковой модели;
- оценка уверенности: `high`, `medium`, `low`;
- передача сложных случаев оператору через `escalate`;
- валидация входных данных и ответа модели;
- ограничение числа запросов на `client_id`;
- журнал обращений и результатов в SQLite;
- безопасный резервный ответ при недоступности LLM;
- локальный запуск и запуск через Docker Compose.

## Как работает сервис

```text
Клиент → FastAPI → валидация → ProxyAPI → проверка JSON → SQLite → ответ
                              ↘ ошибка → fallback → SQLite → ответ
```

Языковая модель получает только текст обращения. Значения `client_id`, ключ
ProxyAPI и содержимое базы данных ей не передаются. Модель настраивается через
переменную `LLM_MODEL`, а адрес API — через `PROXYAPI_BASE_URL`.

## Контракт API

### Запрос

```http
POST /triage
Content-Type: application/json
```

```json
{
  "text": "После ремонта снова появился стук в подвеске.",
  "channel": "chat",
  "client_id": "client-001"
}
```

- `text` — обязательная строка длиной от 1 до 2000 символов;
- `channel` — `email`, `form` или `chat`;
- `client_id` — идентификатор клиента.

### Ответ

```json
{
  "category": "complaint",
  "draft_reply": "Передадим обращение мастеру для повторной проверки.",
  "confidence": "high",
  "escalate": true
}
```

- `category` — `billing`, `support`, `complaint` или `other`;
- `draft_reply` — от одного до шести предложений;
- `confidence` — `high`, `medium` или `low`;
- `escalate` — необходимость передать обращение оператору.

Интерактивная документация после запуска доступна по адресу
`http://127.0.0.1:8000/docs`.

## Настройка

Создайте `.env` на основе `.env.example`:

```env
PROXYAPI_KEY=
PROXYAPI_BASE_URL=https://api.proxyapi.ru/v1
LLM_MODEL=gpt-4o-mini
LLM_TEMPERATURE=0.2
LLM_TIMEOUT_SECONDS=30
DATABASE_PATH=data/triage.db
REQUESTS_PER_MINUTE=10
USE_LLM=true
```

Укажите ключ ProxyAPI только в локальном `.env`. Этот файл исключён из Git и
контекста Docker-сборки.

## Локальный запуск

Требуется Python 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## Запуск через Docker Compose

```powershell
docker compose up -d --build
```

Проверка состояния:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

Остановка:

```powershell
docker compose down
```

Каталог `data` подключается к контейнеру как `/app/data`, поэтому SQLite не
удаляется при остановке или пересоздании контейнера.

## SQLite и журнал обработки

Таблица `tickets` содержит:

- время обработки;
- `client_id`, канал и исходный текст;
- категорию, уверенность и флаг эскалации;
- черновик ответа;
- тип ошибки, если обращение обработано через резервный сценарий.

В технический лог выводятся только безопасные диагностические данные: идентификатор
клиента, канал, длина текста, номер записи и класс ошибки. Ключ ProxyAPI в лог не
попадает.

## Резервный сценарий при сетевой ошибке

Во время проверки Docker-контейнер один раз не смог определить IP-адрес
`api.proxyapi.ru`. Внешнее соединение не установилось, и HTTP-клиент вернул
`ConnectError`.

Сервис продолжил работу и вернул контролируемый ответ:

```json
{
  "category": "other",
  "draft_reply": "Ваше обращение передано оператору автосервиса. Оператор уточнит информацию и свяжется с вами.",
  "confidence": "low",
  "escalate": true
}
```

В SQLite сохранились исходное обращение, резервный результат и тип ошибки
`ConnectError`. После восстановления DNS повторный запрос получил успешный ответ
ProxyAPI, был классифицирован как `complaint` с `confidence=high` и также сохранился
в журнале. Эта проверка подтверждает, что временная ошибка внешнего сервиса не
приводит к падению API и потере обращения.

## Тестирование

```powershell
python -m pytest -q
```

Офлайн-тесты не обращаются к ProxyAPI и не расходуют баланс. Они проверяют:

- доступность `/health`;
- валидацию пустого текста;
- обработку корректного структурированного результата;
- отклонение неизвестной категории;
- ограничение черновика шестью предложениями;
- fallback и запись ошибки в SQLite;
- блокировку лишних запросов и восстановление лимита через минуту.

Текущий проверенный результат: `10 passed`.
